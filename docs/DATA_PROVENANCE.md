# Data Provenance

## Dataset type

This project uses a deterministic synthetic point cloud generated by
`simulated_lidar_publisher.cpp`. It is not a recording from a physical LiDAR
sensor and it is not copied from an external dataset.

## Scene definition

- A square room boundary spans approximately `x/y = -4 m .. 4 m`.
- Wall returns are generated at `z = 0 m` and `z = 0.6 m`.
- A rectangular obstacle spans approximately `x = -1 m .. 1 m` at `y = 1.4 m`.
- The obstacle spans `z = 0 m .. 0.8 m`.
- The scene uses a `0.2 m` construction step and produces 352 points per message.

## ROS2 representation

- Message type: `sensor_msgs/PointCloud2`
- Frame ID: `lidar_frame`
- Input topic: `/points`
- Publish rate: `5 Hz`
- Output topic: `/points_transformed`
- Transformation: 30-degree rotation around the Z axis

## Validation scope

The dataset is useful for reproducible software-in-the-loop validation of:

- ROS2 publisher/subscriber communication.
- `PointCloud2` field handling.
- C++ coordinate transformation.
- RViz visualization.
- Automated geometry and integration tests.

It does not validate physical sensor accuracy. The current scene does not model
LiDAR noise, beam timing, range limits, occlusion, reflectivity, missing
returns, or hardware timing behavior.

`data/sample.xyz` is a separate five-point fixture for the standalone C++ demo;
it is not the source of the live ROS2 scene.
